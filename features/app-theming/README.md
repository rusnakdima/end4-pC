# App window theming

This feature makes external application windows follow end4-pC's light/dark mode
and Material You palette. It is the theme-owned layer that complements the
shell's own theming: when the shell switches mode, the same palette is pushed
to GTK and Qt/KDE applications.

## What it covers

| Toolkit | Applications | Mechanism |
| --- | --- | --- |
| GTK 2/3/4 | Thunar, Nautilus, GNOME apps, … | `adw-gtk3` theme + guarded MD3 CSS block |
| QtWidgets / KDE | Dolphin, Kate, Konqueror, … | Kvantum `MaterialAdw` + KDE `Matugen` scheme + qt6ct matugen palette |
| Qt Quick / Kirigami | KDE Connect and other QML apps | generated `qtquickcontrols2.conf` + `environment.d` variables |

A detector writes `~/.local/state/quickshell/theme-stack/resolved.json` with the
theme actually available on this machine; a deliberately chosen user theme is
preserved. GTK 4 / libadwaita apps keep the host accent — no CSS is injected
into them.

Electron, Firefox, LibreOffice and terminal emulators are **out of scope**;
they have their own theming systems and are handled (if at all) elsewhere.

## How it works

1. The dark-mode toggle calls `switchwall.sh --mode <light|dark>`, whose
   `pre_process()` calls `scripts/theming/app-theming.sh <mode>`.
2. `matugen` regenerates the palette, then `applycolor.sh` calls
   `app-theming.sh --refresh` so the CSS blocks pick up the fresh colours.
   A `post_hook` installed into matugen's `[templates.gtk3]` / `[templates.gtk4]`
   also calls `--refresh`, so the block survives even if that hook fails.
3. `app-theming.sh` renders `gtk3.css.tmpl` / `gtk4.css.tmpl` with the palette
   tokens and writes them between guard markers in the user's `gtk.css` files.
   It never overwrites the rest of the file, so other tweaks survive.
4. For Qt/KDE apps it drives **three** knobs together — all are required for
   an app like Dolphin to actually change:
   - `QT_STYLE_OVERRIDE=kvantum` in `~/.config/hypr/hyprland/env.lua`
     (set by `install.sh`; **needs a logout/login** for already-running Hyprland),
   - Kvantum's active `theme=MaterialAdw` in `~/.config/Kvantum/kvantum.kvconfig`
     (so `materialQT.sh`'s light/dark Colloid kvconfig is used),
   - `color_scheme=matugen` in `~/.config/qt6ct/qt6ct.conf`
     (so Qt widgets pick up the matugen palette).

   The KDE scheme name `Matugen` matches the real
   `~/.local/share/color-schemes/Matugen.colors` file generated by matugen.

> Thunar (GTK3) already receives its Material You / MD3 look from the
> matugen-generated base `gtk.css`. The guarded block here reinforces that look
> and adds Thunar-focused selectors; it is not the sole source of the styling.

## Config keys

Under `appearance.appTheming` in `~/.config/illogical-impulse/config.json`
(edit from **Settings → Appearance → App theming**):

| Key | Default | Meaning |
| --- | --- | --- |
| `enable` | `true` | Master switch for the whole layer |
| `gtk` | `true` | Apply GTK 2/3/4 theme + CSS |
| `qt` | `true` | Apply Kvantum MaterialAdw + KDE `Matugen` scheme |
| `manageQtStyle` | `true` | Drive Kvantum theme + qt6ct colour scheme (requires re-login for `QT_STYLE_OVERRIDE`) |
| `perApp.thunar` | `true` | Thunar-focused MD3 selectors in GTK3 CSS |
| `perApp.dolphin` | `true` | Dolphin-focused KDE scheme handling |
| `refreshRunningApps` | `true` | Signal running apps to re-read settings (also restarts KDE Connect) |
| `qtQuick` | `true` | Write `qtquickcontrols2.conf` and the Qt Quick environment variables |
| `provision` | `true` | Re-detect the compatible theme stack on every mode change |
| `preferredFamily` | `auto` | Theme family preference: `auto`, `adwaita`, or `colloid` |

Toggles are read at the next mode/palette change. Some applications (notably
GTK3 ones) only re-read their CSS at startup, so restart them if a change does
not appear immediately. **KDE Connect** reads the Qt Quick mode at startup, so
with `refreshRunningApps` enabled its running process is restarted once on a
mode change. Hyprland and other already-running apps still need **one
logout/login** before they pick up the environment variables for the first time.
Dolphin's Kvantum path is unchanged; Thunar's toolbar/path-bar borders are
removed inside the guarded CSS block.

Use **Settings → Appearance → App theming → Re-detect themes** after installing
a theme yourself to refresh `resolved.json`.

Installer opt-outs: `APP_THEMING=0`, `APP_THEMING_QT_ENV=0`,
`APP_THEMING_MATUGEN_HOOK=0`, `APP_THEME_PACKAGES=0`, or the flags
`--no-app-theming`, `--no-app-theming-qt-env`, `--no-app-theming-hook`,
`--no-theme-packages`.

The full window-type catalog, fallbacks and design decisions live in
`docs/design/theme-stack.md`.

## Adding a sink

`manifest.json` is the declarative extension point: each sink names a toolkit,
the applications it targets, the config key that gates it, and the files it
writes. To support a new toolkit:

1. Add a sink entry to `manifest.json`.
2. Add a `*.tmpl` template if the sink needs generated content.
3. Add a guarded apply function in `scripts/theming/app-theming.sh` and call it
   from `apply_all()`.

The shell script is authoritative at runtime; the manifest documents the
contract so a sink can be reviewed without reading bash.

## Tests

- `tests/app-theming/test_app_theming.sh` — 22 checks against a throwaway `$HOME`
  (file-level behaviour: both modes, placeholders, guard markers, idempotency,
  `--refresh`, and the Qt/KDE knobs).
- `tests/app-theming/test_app_theming_render.sh` — launches real Thunar and
  Dolphin on Xvfb `:99`, screenshots them in both modes, and samples pixels to
  prove the palette actually changes. This is the gate that catches a Qt style
  override silently cancelling the theme.
