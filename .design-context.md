# Design Context — Custom Window Controls (end4-pC)

## Feature
A shell-drawn window-control cluster for Hyprland: Windows-like **minimize / maximize / close** plus a **fourth button that changes the window type** (floating / tiling / stacking, with span as an existing special case).

## Response / artifact language
English. `.design-context.md` and `DESIGN.md` are technical artifacts; prose stays in English even though the project ships localized READMEs (README.ja.md, README.zh-CN.md) and a translation system under `translations/`.

## Source of truth for this context
User's own words (verbatim, collected during the design conversation):

- Initial request: "i want talking about with you about window controls (titlebar controls). i want integrate custom him into windows/hyprland theme @end4-pC/ that have buttons close maximize minimize and also 4 button change type floating and tilling types (tilling/stacking). go thinking and prepare plan"
- Clarification on button semantics: "4th button change type window type, and 3 buttons as like in windows with same behavior, hide should be really hide but in dock i should be see and alt tab also (alt tab i have)"
- Clarification on placement: "try floating overlay and on fallback into bar"
- Clarification on visual style: "Material 3 native (Recommended)"

## Interpretation adopted
- The cluster has **four buttons**: minimize, maximize, close (Windows-like behaviour), and a **window-type selector** as the fourth.
- The fourth button exposes the type choices **floating / tiling / stacking** (and **span**, which already exists as a per-app rule) — most naturally via a small flyout/menu opened from that button. The flyout contents are a documented, easily changed assumption.
- **Minimize must be a true hide** — the window leaves the screen — but the window **must remain visible in the dock and in alt-tab**. Alt-tab is the existing `WindowSwitcher`.
- Placement: **floating overlay anchored to the active window** is the primary target; a **bar-mounted fallback** is required.
- Visual direction: **Material 3 native**, reusing the shell's `Appearance.*` tokens.

## Project constraints (observed, not assumed)
- This is a QuickShell (QML) shell, a fork of illogical-impulse/dots-hyprland. It requires illogical-impulse to be installed.
- QuickShell cannot inject widgets into third-party app windows. Native titlebar buttons are toolkit-side and are **disabled by default** by `install.sh` (`DISABLE_WINDOW_BUTTONS=1`; see `install.sh:285` and `README.md:205`).
- Hyprland draws no titlebars; there is no `hyprland.conf` option for window buttons.
- Existing infrastructure to reuse:
  - `services/WindowMode.qml` — global `tiling`/`stacking` mode, per-app `tiling`/`stacking`/`span` rules, `setMode()`, `IpcHandler` target `windowMode`.
  - `services/WM.qml` / `services/HyprlandBackend.qml` — `closeWindow()`, `focusWindow()`, `Hyprland.dispatch("hl.dsp.window.close(...)")`.
  - `services/WindowMode.qml:652` — `setFloat()` via `hl.dsp.window.float({ ..., action = "set"|"unset" })`.
  - `services/HyprlandData.qml:148` — raw events include `activewindow`, `changefloatingmode`, `fullscreen`, `minimize`; clients expose `address`, `class`, `title`, `at`, `size`, `monitor`, `floating`, `fullscreen`, `workspace`, `focusHistoryID`, `hidden`, `mapped`.
  - `welcome.qml:89`, `modules/ii/overlay/StyledOverlayWidget.qml:309`, `modules/common/widgets/DragApps.qml:502` — established `RippleButton` + `MaterialSymbol` control-button pattern.
  - `modules/ii/bar/ActiveWindow.qml` — the bar fallback host.
- **Critical conflict found:** `modules/ii/windowSwitcher/WindowSwitcher.qml:174` skips clients where `windowData.hidden || windowData.mapped === false`. A minimize implementation that marks a client hidden would remove it from alt-tab unless that filter is changed. The dock service (`services/TaskbarApps.qml`) has no such filter, so the dock path is already compatible.

## Target audience
Hyprland power users running end4-pC who prefer a clean, button-free app titlebar and want shell-level control of window state and layout mode.

## Brand personality / aesthetic
Material 3 Expressive: premium, calm, tactile, restrained. No skeuomorphism, no Windows chrome beyond the familiar button ordering and behaviour.

## Accessibility target
WCAG 2.2 AA adapted to a desktop QML context: visible tooltips, keyboard focus traversal, sufficient contrast via theme roles, and icon+label (never colour alone) for active/inactive type state.

## Reference sites / vendor seeds
None. No vendor branch applies; design proceeds from the existing shell design language (no getdesign/Stitch seed).
